## 結論

ペース計算（F-05）と通知の状態機械（F-07）を、境界値・状態遷移とも同一ロジックの再現で検証し全項目合格（(A)）。**GUI 表示・トースト通知・WebView2 連携を伴う (B) は未実施であり、Windows 実機での確認が必要。**

## 1. (A) 机上ロジック検証（実施済・合格）

| 使用 100% | 上限 → ETA 0・持たない | 一致 |

| 経過 60%・使用 66% | SlightlyAhead / delta +6 / ETA 約 92.7 分 | 一致 |

## 3. 実機確認の推奨手順

1. Windows で `dotnet build -c Release`（B-00）。
2. Claude ログイン後、使用が進んだ状態でペース行の各状態を確認（B-02〜B-04）。設定でペース OFF/ON（B-06）。
3. 閾値付近まで使用して通知の跨ぎ・再通知なし・リセット後再通知を確認（B-07/B-08）。100% 通知（B-09）。
4. ネットワーク切断で stale にし、通知が出ないこと（B-10）。
5. 既存 settings.json のまま起動で後方互換（B-13）。
