## 結論

適応更新間隔（F-10）の判定を境界値で検証し全項目合格（(A)）。**タイマー実挙動・トレイメニュー・WebView2 巡回停止を伴う (B) は未実施であり、Windows 実機での確認が必要。**

## 1. (A) 机上ロジック検証（実施済・合格）

### 1.1 F-10 `AdaptiveRefreshPolicy.Compute`（基準 30 秒）

| 条件 | 期待 | 結果 |
|---|---|---|
| 電源制約（バッテリー残僅少） | 30 分 | 一致 |
| オーバーレイ非表示 | 15 分 | 一致 |
| 操作直後（0〜5 分） | 30 秒（基準） | 一致 |
| 最終操作 30 分前 | 2 分 | 一致 |
| 最終操作 2 時間前 | 5 分 | 一致 |
| 最終操作 6 時間前 | 15 分 | 一致 |
| 基準間隔 2 秒（極小） | 5 秒へクランプ | 一致 |
| 非表示かつ電源制約（優先順位） | 30 分（電源が最優先） | 一致 |

判定順（電源制約 → 非表示 → 経過時間帯）が仕様どおり機能。

## 3. 実機確認の推奨手順

1. Windows で `dotnet build -c Release`（B-00）。
2. 起動後しばらく放置し、間隔が延びること／操作で戻ることを確認（B-01/B-02）。一時的に `StatusText` へ現在間隔をデバッグ表示すると確認しやすい。
3. オーバーレイを非表示にして間隔延長（B-03）。ノート PC をバッテリー駆動＋低残量にして 30 分間隔（B-04）。
4. トレイからスヌーズし、StatusText・トレイ減光・WebView2 停止を確認（B-06〜B-08）。↺/再開で解除（B-09）。
5. 既存 settings.json のまま起動で後方互換（B-11）。
