## 結論

純ロジック（閾値レベル判定・バー塗り幅・マーカー座標・リセット表示分岐）は境界値を含めて机上検証で期待どおり動作することを確認した（(A) 合格）。**GUI・トレイ・DPI・stale 減光・WebView2 連携を伴う実機項目 (B) は未実施であり、Windows での `dotnet build -c Release` と exe 起動による確認が必要。** 下表の (B) 項目をリリース前に消化すること。

## 1. (A) 机上ロジック検証（実施済・合格）

### 1.1 F-03 `UsageLevelHelper.GetLevel`（既定 注意 50 / 警告 80）

| 入力% | 期待 | 結果 |
|---|---|---|
| -5, 0, 49 | 通常（緑 #4CAF50） | 一致 |
| 50, 79 | 注意（オレンジ #FF8C00） | 一致 |

境界（50 で注意開始、80 で警告開始、範囲外もクランプせず判定成立）を確認。

### 1.2 F-01 `TrayIconRenderer` 上段バー塗り幅（幅 w=28、整数スナップ）

| 入力% | 塗り幅 | 備考 |
|---|---|---|
| 0, 1 | 0px | 1% は round(0.28)=0 → トラックのみ（塗りなし）。ほぼ 0 のため妥当 |
| 2 | 1px | 2% から 1px 描画 |
| 25 / 50 / 80 / 100 | 7 / 14 / 22 / 28px | 比例。100% で全幅 |
| 125 | 28px | 100 にクランプ |

### 1.3 F-03 `ThresholdMarkerOverlay` マーカー X 座標（ActualWidth=200）

| 閾値% | X | 備考 |

| 50 | 100.5 | 0.5 オフセットで 1px 線をくっきり描画 |
| 80 | 160.5 | 同上 |
| 0, 100 | 非描画 | 端に潰れるため `continue`（設計どおり） |

### 1.4 F-04 `BuildResetText`（基準時刻 2026-07-06 10:00）

| 条件 | 期待 | 結果 |
|---|---|---|
| absolute・当日 14:32 | `14:32 リセット` | 一致 |

## 3. 実機確認の推奨手順（B 項目）

1. Windows で `dotnet build -c Release`（B-00）。エラーがあれば `REVIEW` §4 の静的検証観点を起点に修正。
2. `dotnet run` で起動し、Claude ログイン後にトレイ 2段バーとオーバーレイを目視（B-01, B-06, B-07）。
3. タスクバーの DPI を 100/125/150% に変更して再確認（B-02）。
4. 機内モード等でネットワークを一時切断し stale 減光を確認、復帰で戻ることを確認（B-04, B-05）。
5. 設定画面で閾値・形式・マーカー・不透明度を変更し即時反映を確認（B-03, B-08, B-12, B-13）。
6. 既存の `%AppData%\AIUsageOverlay\settings.json` を温存したまま起動して後方互換を確認（B-14）。
